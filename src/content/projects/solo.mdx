## Context

Solo is an agent harness I built alone, from scratch, to learn how agent systems work by building every part of one: the loop, the tools, the permissions, the memory, sub-agents and tracing. It became something I use. You type an errand in plain words, like "text Mom I'm running late, play xe3, and book the cheapest flight to Goa on Friday", and it does the work in the background while you keep using your computer.

It runs on your own machine. `pnpm start` installs what it needs the first time and opens the dashboard on localhost. Each model step runs on your Claude Code login, so there's no API key to set up.

It's TypeScript (ESM, strict) end to end, with a Next.js 16 dashboard, a Chrome extension and a small Swift helper for Mac accessibility.

## What's in it

### Your own browser

By default the agent works in its own Chromium window. With the Solo Bridge extension it works in your everyday Chrome, Comet, Brave, Arc or Edge instead, logged in as you. It can find a tab you already have open ("reply in my Gmail tab", "play the video I paused") and opens its own tabs in a background tab group, so your tab stays in front.

You decide what it sees. Exclude a tab and the agent never knows it exists, or switch to "only tabs I share". Nothing connects without the pairing code.

### Your Mac apps

Spotify, Notes, Mail, WhatsApp and the rest. Apps with AppleScript get AppleScript, kept inside that one app. Everything else goes through the accessibility API: the Swift helper lists numbered buttons and fields, and the agent acts on a number after the role is checked again. Terminals, password managers, System Settings and browsers are off limits.

### You approve what matters

Every action asks once per site or app, with "allow once", "for this session" or "always". After the agent reads a web page or a message, the rules tighten. Payment fields and Pay buttons are refused in code, and the agent asks you before anything that speaks or commits for you.

### Sub-agents, research and critic

`spawn_agent` hands independent parts of a task, like three booking sites or five questions, to sub-agents that run at once, up to four at a time, each with only the tools it needs. Research mode turns the main agent into an orchestrator that splits the question and writes the synthesis. Critic mode has an independent reviewer check each answer and send it back for up to two revisions.

### Every step on record

The trace view shows every turn, model step, tool call, sub-agent, token and dollar. `pnpm trace` prints the same tree in the terminal, and runs export to OpenTelemetry with the GenAI conventions, so they open in Jaeger, Grafana Tempo or Langfuse.

## Constraints

- Everything listens on 127.0.0.1, and the local API rejects writes from other origins.
- The model's input can be written by an attacker once it reads a page, so tool output is data and every side effect goes through the permission hook.
- Every limit is bounded: steps per turn, output size, per-tool time, sub-agent depth and concurrency, and a loop guard for repeated failing calls.
- `run_command` is not a sandbox. It asks before each call and strips credentials from the environment, but container isolation is still on the roadmap.

## Results

- On blazedemo.com it searched flights, picked the cheapest, filled passenger details and stopped at payment, handing over to me.
- Working in a background tab of a visible browser, a click took 60 ms and typing 65 ms, with my own tab staying in front.
- A program pretending to be the harness on the extension's port got only the pairing proof: 0 commands run and 0 tabs opened.
- Through the accessibility API it pressed 7, +, 2, = in Calculator and read back 9, at about 0.6 s per press.
- Two sub-agents in parallel, each with one tool, finished in 2 steps and 17k input tokens.
- What doesn't work yet: Spotify's window exposes nothing to accessibility, some apps ignore background keystrokes, and sites with strong bot protection can still block the agent's own browser. Evals (M9) are next.
