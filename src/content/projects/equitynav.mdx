## Context

EquityNav is an equity management product built by a client of Heizen. I worked on it as a software development engineer intern at Heizen from August 2025 to January 2026, remote.

The product helps people understand their equity: when shares vest, what exercising costs, and what liquidity could look like. I worked on two parts of it. The first was a set of AI insight agents that answer questions in those three areas. The second was the data side: bringing Carta portfolios and an equity-tax engine together into dashboards, and keeping that data current.

No public link for this one. It's client work, so I'm describing it at the level of my resume and leaving internal details, data and anything about the client's users out of it.

## What's in it

### Insight agents

I built the agents on the Vercel AI SDK, with OpenAI and Gemini as the model providers. The SDK gives both providers the same interface, so I didn't write the agent code twice.

The agents cover three topics: vesting, exercises and liquidity. Each of these comes down to specific numbers in a person's data, like a vesting date or the cost of an exercise, and a model guessing at those is worse than no answer at all. So the agents don't answer from memory. They call tools. One of those tools runs SQL, which means the numbers in an answer come from a query against the data.

### Structured outputs and guardrails

Free text is hard to check. I had the agents return structured outputs, so each answer has a known shape that the app can validate and show. An agent that can run SQL also needs limits, so guardrails sit around what it may call and what it may return. The specific rules stay private.

### Dashboards

On the data side, I unified Carta portfolios with an equity-tax engine and built three views on top: projection, scenario and risk.

### Sync and alerts

Stale data makes a dashboard wrong. Quietly. I automated the Carta sync and the alerts with NestJS Scheduler, so they run on a schedule without anyone triggering them. The services ship in Docker, and builds run through GitHub Actions.

## Constraints

- Answers about equity had to rest on real numbers, not on what a model guesses.
- The agents needed to work with two model providers.
- Portfolio data came from Carta and had to stay in sync without manual steps.
- It's client work with no public link, so I keep the details at resume level.
